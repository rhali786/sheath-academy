## Headline finding — read this first

**`page.goto('/')` after `loginDev(page)` no longer reaches the Dashboard.**

`/` (`app/(public)/page.tsx`) is now an intentionally public marketing landing page for
*everyone*, including signed-in users (`middleware.ts:15-18`, comment "Landing page is
public — show it to everyone regardless of auth state"). The actual dashboard moved to
`/dashboard` (`app/(shell)/dashboard/page.tsx`). There is no post-login redirect from `/` to
`/dashboard`.

**This single issue accounts for ~28 of the 63 remaining failures** (see "HEADLINE FINDING"
rows in the table below), across 6 spec files:
`dashboard.spec.ts`, `dashboard-student-isolation.spec.ts`, `dashboard-evidence-empty-
state.spec.ts`, `dashboard-learning-activity.spec.ts`, `dashboard-selected-child-
regression.spec.ts`, `quran-session-dashboard-update.spec.ts`.

**Recommended B2 fix:** mechanically replace `page.goto('/')` immediately after
`loginDev(page)` with `page.goto('/dashboard')` in these 6 files, then re-run to find the
(much smaller) set of genuinely new failures underneath.

## Second-most-common issue — `selectOption({ label: <RegExp> })`

Playwright's `locator.selectOption({ label })` requires a `string`, not a `RegExp`. Passing
a regex (e.g. `{ label: /Khadijah/i }`) throws `"options[0].label: expected string, got
object"`. **Accounts for ~14 failures** across `dashboard-student-isolation.spec.ts`,
`dashboard-evidence-empty-state.spec.ts`, `dashboard-learning-activity.spec.ts`,
`dashboard-selected-child-regression.spec.ts`, `learning-time.spec.ts`,
`lesson-completion-report.spec.ts`, `archive-dashboard-filtering.spec.ts`,
`quran-session-dashboard-update.spec.ts`.

**Recommended B2 fix:** replace `selectOption({ label: /Name/i })` with
`selectOption({ label: 'Name' })` (exact string) everywhere this pattern appears (grep for
`selectOption({ label: /`).

---

## Third issue — Next.js route announcer collides with `getByRole('alert')`

Next.js renders a hidden `<div role="alert" id="__next-route-announcer__">` on every page
after navigation. Any test using `page.getByRole('alert')` (expecting it to match only an
app-rendered validation/status message) gets a strict-mode violation or an unexpected
count ≥ 1. **Accounts for 4 failures** in `report-date-validation.spec.ts` and 1 in
`feedback.spec.ts`.

**Recommended B2 fix:** scope these locators more specifically — e.g. add a dedicated
`data-testid` to the app's own alert element (`ReportsPage.tsx:144`) and target that, or use
`.filter({ hasNotText: ... })` / exclude `#__next-route-announcer__`.

## Suggested B2 phase breakdown

1. **Headline fix** — `goto('/')` → `goto('/dashboard')` in the 6 affected spec files
   (~28 failures), then re-triage what's left in those files.
2. **`selectOption({ label: regex })` → string** — grep-and-fix across all affected files
   (~14 failures, overlapping with #1).
3. **Route-announcer `role="alert"` collisions** — add a dedicated testid/locator for
   app-rendered alerts in `ReportsPage.tsx` and feedback detail page (~5 failures).
4. **ShellAuthGuard vs. middleware-public routes** (`/about`, `/feedback` signed-out state)
   — decide whether these pages move out of `(shell)`, or `ShellAuthGuard` gets an
   allow-list (~3 failures).
5. **Layout drift (`max-w-5xl` vs `max-w-7xl`)** on `/portfolio` (Growth) and `/reports`
   — confirm against `ui-style-guide` and either update the pages or the tests (~4
   failures).
6. **Remaining one-offs** — `auth-fallback-credentials` selector exactness, `attendance`
   collapsed form + combobox specificity, `alerts-links` Surah label association,
   `archive-dashboard-filtering` combobox timeout, `lesson-status-sync` `/planner` vs
   `/plan` route + status-filter investigation, `planner.spec.ts` orphaned
   `ScheduleNowNextCard`, `product-validation` CTA route mismatch, `feedback.spec.ts` route
   announcer.
